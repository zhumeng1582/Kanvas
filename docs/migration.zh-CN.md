# 版本、API 稳定性与迁移

## 当前状态

Kanvas `0.1.0` 是开发版本。仓库当前支持源码工程和工作区 Maven 仓库接入；在发布公告给出
正式坐标之前，远程 Maven 坐标不属于受支持的安装契约。

构建使用 Kotlin 二进制兼容性校验器，各库模块的公开 API 基线保存在 `api/` 目录。
`./gradlew apiCheck` 可以发现意外签名变化，但校验通过不代表行为、渲染、持久化格式或实验性
接入点已经稳定。

## 兼容策略

- 在 `1.0.0` 之前，次版本之间允许调整公开 API；有意的破坏性变更必须同时记录到
  `CHANGELOG.md` 和本文对应版本章节。
- 补丁版本原则上保持源码和二进制兼容。若现有契约无法按文档安全使用而必须修正，发布说明
  必须明确标出例外。
- 带实验性注解的 API 在移除注解前不提供兼容保证；未标注 API 仍受上述 `0.x` 策略约束。
- `KlineCandle` 顺序、毫秒时间戳、指标列 newest-first 对齐，以及绘图的时间戳/数值坐标属于
  数据契约。即使 Kotlin 签名不变，修改这些约定也必须提供迁移路径。
- 绘图序列化格式由宿主持有。宿主应给存储结构增加版本，并在仓库边界转换为当前
  `DrawingOverlay` 模型。

## 升级源码接入

1. 阅读从当前 revision 到目标 revision 之间的 `CHANGELOG.md`。
2. 审查所有已依赖模块的 `api/*.api` 差异。
3. 重新构建行情适配层，验证 newest-first、分页去重、毫秒时间戳和必填 OHLCV。
4. 至少恢复两个交易对的绘图，确认切换时先保存旧会话，再恢复新会话。
5. 检查自定义指标和主图 Renderer 的缓存策略；只有输出完全取决于不可变输入时才使用
   `ImmutableInputs`。
6. 在业务支持的设备矩阵上运行 JVM 测试、Example Release 构建、Lint 和设备测试。

## 版本迁移记录

`0.1.0` 之前没有受支持的 Kanvas 远程发布版本。以后每个破坏性版本都应在发布前于此补充
具体的变更前后代码和数据迁移步骤。
